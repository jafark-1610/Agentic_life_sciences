# Expert pipeline

`run_pipeline.py` accepts `--data`, `--output-dir` and `--config`. Its default `config/parameters.yaml` is JSON-compatible YAML. It validates inputs, enumerates the full response-function family, assembles all observational and randomized-design constraints, solves the sharp conditional bounds, selects the policy, validates the schema and writes the two result artifacts. Internal enumeration comprises 1296 response/assignment types per true-genotype stratum; both strata retain separate arbitrary probability laws.

`causal_model.py` implements observation operators, target paired-world coefficients and fractional optimization. Measurement noise is integrated with its stated independence and counterfactual retention. Biological response and natural-assignment functions are allowed to be arbitrarily dependent. `expert_solution.py` loads the full tables and derives every answer at runtime; it does not read private generation laws or stored answers. `artifacts.py` serializes numeric oracle values to five decimals, generates diagnostic report evidence, and leaves solver precision unrestricted.

`analysis.md` proves completeness of the finite response-family representation and explains the conditional optimization. `final_answer.json` is the canonical computed answer. `results/final_answer.json` and `results/analysis.md` are the completed oracle output snapshot. `results/verification_result.json` records actual isolated execution, runtime versions, source hashes, private-path denial, mounted permissions, network isolation, regenerated-input scoring and stored-answer rejection. `results/execution_record.json` is an evaluator-generated execution record, not a solver deliverable or configured solver slot. `results/cross_runtime_comparison.json` records portability checks. `evaluation_status.json` distinguishes local checks from actual external model runs and qualification.

`score_rubric.py` accepts `--answer`, `--data`, `--artifacts-dir` and optional `--output`. It grades sharp endpoints, global envelopes, identification and policy choice, recovers the documented presentation variants before science, and checks the structured report block. A numerical answer verdict does not establish code execution or input dependence.

`verify_submission.py --solver PATH --data task/data --output-dir OUTPUT --replay-control` is the full submitted-code verifier. It requires Linux bubblewrap and unprivileged namespaces. A capability failure returns blocked/status 2, a scientific/execution failure returns 1, and success returns 0. The verifier derives a physically consistent regenerated table set, independently recomputes trusted expected bounds, and requires both base and regenerated submitted executions to pass. It also executes a stored-answer control. No solver-generated execution-summary file is requested. `private/generation_laws.json` is used only for synthetic-data provenance and trusted regeneration.

`tests/test_package.py` checks scientific scoring, schema, presentation variants, artifact diagnostics, the exact three-slot contract, observation normalization and an analytic fractional example. `tests/independent_oracle.py` independently assembles the response family in a different column order and checks conditional extrema by linear-objective bisection rather than the main transformation. `tests/result.json` records package tests. `robustness_checks/` records independent calculations, a perfectly compatible point-law failure, an independent-world failure, conditional-ratio approximation behavior, reference margins and contract checks. These controls are not solver model trials.

`build_rubric_md.py` generates both rubric views from public rules and computed dimensions. `rubric_results.json` and `rubric_results.md` record canonical scoring. `source_archive/generate_data.py` recreates the synthetic fixtures. `validate_package.py` checks the package against the declared three-slot contract; it cannot configure or verify the evaluation service's UI or file-ingestion state. If the service cannot read the uploaded task and substitutes its own fallback list, that ingestion issue must be resolved by the service rather than by adding a solver output. `freeze_package.py` locks all scientific and executable content while excluding regenerated execution records, test results, robustness results and external evaluation status.
