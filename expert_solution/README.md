# Expert pipeline

From the package root, execute the commands in the root README. `run_pipeline.py` accepts `--data`, `--output-dir` and `--config`; defaults resolve relative to its location. `config/parameters.json` selects the polyhedral minimax-regret method and HiGHS solver. The pipeline checks the input, solves the flux and decision problems, validates the full JSON schema and writes the answer, analysis and execution summary.

`expert_solution.py` computes every result from staged inputs. `final_answer.json` is the canonical computed output. The grader accepts `--answer`, `--data` and optional `--output`, returns process status 0 for pass and 1 for fail, and reports all scientific groups. `build_rubric_md.py` generates both rubric files; `--check` detects drift. `tests/independent_oracle.py` independently assembles the constraints and computes support values, including primal/dual agreement.

`tests/test_package.py` checks numerical science, schema, grading mutations and consistency. `robustness_checks/run_checks.py` records perturbation and alternative-method evidence in `result.json` and `result.md`. `source_archive/generate_data.py` reconstructs the synthetic inputs using a fixed seed. `private/generation_truth.json` records the generated feasible states for provenance; neither the analysis nor grader reads it. `results/` stores the scientific report and current execution summary. `freeze_package.py` fixes scientific-content hashes and detects subsequent changes. Runtime evidence in results/, robustness result files, rubric result files, test results and external-evaluation status is excluded so these checks can be rerun without changing the scientific freeze. Regeneration is an authoring operation; it must not occur during model evaluation.

`rubric_results.json` and `rubric_results.md` record numerical grading of the canonical output. `tests/result.json` records local package-test execution. `evaluation_status.json` records the external evaluation stages and their execution status.
