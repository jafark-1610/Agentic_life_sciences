# Expert workflow

`run_pipeline.py` accepts `--data`, `--output-dir` and `--config`. The default `config/parameters.yaml` uses JSON-compatible YAML syntax and requires no YAML dependency. The pipeline checks data, calibrates sensors, performs bounded nonlinear inversion, enumerates the complete compatible model set, simulates all course/model/scenario cases and writes the three required output artifacts.

`mechanism.py` handles pulse jumps, time-dependent blockade and continuous maxima. `expert_solution.py` implements inversion and course selection. `artifacts.py` generates structured report evidence and exact input/output hashes. `final_answer.json` is the canonical computed answer. `results/` contains execution and verification evidence. `private/generation_truth.json` is used for author validation and trusted regenerated-data construction; the inference pipeline does not read it.

`score_rubric.py` accepts `--answer`, `--data`, `--artifacts-dir` and optional `--output`. It recovers the documented presentation variants before grading, matches models by their parameter equivalence, recomputes measurement fit and a physical peak witness, and checks diagnostic/report hashes. Its scientific-answer verdict alone does not prove that submitted code runs or depends on inputs.

`verify_submission.py` is the full submitted-code entry point. It accepts `--solver`, `--data`, `--output-dir`, optional `--seed`, `--timeout` and `--replay-control`. It requires Linux bubblewrap with user/network namespaces, stages only public task and submitted source files, and mounts the Python runtime read-only. It verifies private-path denial, read-only task files, and network isolation before any submitted pipeline runs. A missing capability is blocked with process status 2; a verified submission failure returns 1; success returns 0. Original and regenerated runs must both pass. Regeneration changes actual physical parameters and sensor signals, updates integrity hashes, and recomputes trusted expected counterfactuals. The replay control checks a stored answer even after refreshing its provenance hashes. `regenerated_data.py` performs trusted-side data regeneration.

`tests/test_package.py` checks scoring, presentation, delivery, symmetry, independent dynamics and integrity. `tests/independent_oracle.py` independently implements the declared ODE and event mechanics using Radau and a finer extremum mesh. `tests/result.json` records package-test execution. The robustness workflow records independent calculations, baseline procedures and gate margins. `rubric_results.json` records canonical scoring. `build_rubric_md.py` generates both rubric views from public tolerances and computed dimensions. `source_archive/generate_data.py` recreates synthetic inputs. `freeze_package.py` locks scientific inputs, executable policy, canonical answer and documentation while excluding generated results, test/robustness evidence, rubric result files and external evaluation status. `evaluation_status.json` records which external evaluation stages have actually executed.

`compare_answers.py` is the oracle execution comparator. It uses the scientific grader rather than exact float equality, accepts equivalent model ordering, and validates peak times through the physical model. The generated rubric includes explicit JSON Pointer tolerance paths as well as the unchanged scientific thresholds. Oracle output serialization retains eight decimal places for scientific floats and a millihour peak-time coordinate; the peak value is recomputed at that coordinate from the serialized parameters. This policy does not impose decimal-place requirements on solver answers. `tests/fixtures/oracle_runtime_drift.json` records reported cross-runtime values for regression testing.

`results/cross_runtime_comparison.json` records exact answer equality across two Python/NumPy/SciPy environments. `results/correction_scope.json` records that scientific inputs, algorithms and scoring thresholds were preserved during execution-compatibility maintenance. `results/oracle_execution.json` and `results/verification_result.json` record completed oracle and isolated replay verification.
